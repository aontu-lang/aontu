Three defects stand between the current tree and a release that could be
recommended. The first two **block** it — shipping either would put a
hazard in users' hands — and the third **bounds what it delivers**:

1. **The MCP server executes caller-supplied code.** Four of its six
   tools ignore the confinement the module and the public API reference
   both claim, and `@"…"` on a `.js` path is `require()`d.
2. **The two ports disagree on `vet`'s verdict, in both directions.**
   Go answers `valid` where TypeScript answers `invalid`, and `error`
   where TypeScript answers `valid`. Neither direction is recorded.
3. **The repair loop has no third step.** `aontu set` cannot narrow a
   pinned literal, which is the shape of the most common `vet` failure,
   and the manual fallback is unsafe because a `Site` has no extent.

Everything else found — and there is a lot of it — ranks below getting
to that release, because a capability nobody can install has no users to
affect. The ranked [Next](#next) puts the two blockers first and the
release immediately behind them.

## The method, and its confidence

Fourteen agents: seven drove one surface each (MCP, the CLI loop, the
skill and docs, the grammar, the register, build/test/parity, and the
forward gaps), and seven adversarial verifiers independently re-ran their
load-bearing claims. The verifiers refuted 22 claims and corrected 38
more out of ~150 checked, so **the raw first-pass findings were about 15 %
wrong** and the corrections are folded in below. Every claim in this file
that carries a consequence was then re-run a third time by hand; the
commands are in the text.

Two first-pass claims were withdrawn outright and are recorded here so
they are not rediscovered: `[&: T]` **is** a working homogeneous-list
schema in both ports (`a: [&: string]` accepts `["x","y"]`, refuses
`["x",7]` at `$.a.1`, and accepts `[]`, which positional `[string]` does
not) — the gap is only that the skill never shows `&:` on a list; and
ANSI escapes in `--format json` are JSON-encoded text, not raw control
bytes, so captured JSON diffs cleanly. The text surface is the one with
raw escapes, and it honours neither `NO_COLOR` nor `FORCE_COLOR`.

## 3. The MCP server must not ship as it stands

The wire protocol is right, and that is the hard part. The official
`@modelcontextprotocol/sdk` 1.30.0 client connects to
`node ts/bin/aontu-mcp.js` with no adaptation, negotiates, lists six
tools (`vet`, `get`, `why`, `diff`, `canon`, `summary`) and calls them.
Framing is correct NDJSON JSON-RPC 2.0 and reassembles across 7-byte
chunks; stdout carries only protocol frames; the *"a refusal is an
answer"* contract (`ts/src/mcp.ts:219-223`) is honoured, so a
contradiction comes back as a report with `isError: false` and an agent
never has to tell transport failure from semantic failure. The tool
descriptions are unusually good LLM-facing prose.

Then it runs whatever you send it.

```
tools/call get { src: 'a: @"/abs/path/pwn.js"', path: '$' }
```

`pwn.js` is `require()`d and its top-level statements execute. Verified
here directly: a canary file was written to disk by the server, from a
caller who supplied nothing but a source string, and the tool then
returned an `internal` finding — so **the execution is invisible in the
report**. The same channel reads arbitrary files: `get` returns
`/etc/passwd` in `out`, and `why` leaks contents through
`record.conjuncts[].canon` while its `site.file` stays empty, so grepping
`site.file` for disclosure would clear a tool that is leaking.

The cause is structural rather than a slip. `served()`
(`ts/src/mcp.ts:66`) is called at only two sites, `:173` and `:184`, so
`canon` and `summary` correctly answer `include_denied` while `vet`,
`get`, `why` and `diff` do not — because those four delegate to library
functions that each construct a bare `new Aontu()` (`ts/src/vet.ts:349`,
`ts/src/query.ts:264` and `:328`, `ts/src/diff.ts:175`) and expose no
trust option at all. **There is also no trust knob on the MCP surface** —
no flag, no environment variable, no `initialize` option — so a host
cannot confine the server even knowing this, and the same hole is open on
the command line: `aontu get '$.x' --trust none doc.aon` answers
`unknown get option --trust` and exits 2, while `--trust` is printed
under the general `Options:` heading of `--help`.

Two documents state the opposite and need correcting in the same change:
`ts/src/mcp.ts:16-19` (*"The server evaluates under a CONFINED
resolver"*) and `docs/reference-api.md:652-654` (*"Served evaluation is
confined to no includes"*).

The single confinement test, `ts/test/mcp.test.ts:126`, exercises `canon`
alone — one of the two tools that is confined.

**Three inputs kill the process outright**, with no reply and every
queued request lost, because nothing wraps tool execution in a
`try`/`catch`:

| input | failure |
|---|---|
| `src: "$"` (one byte) | `TypeError` at `ts/src/query.ts:226`, inside the `evalFailure` branch whose own comment calls the state impossible. Go answers this input correctly, so it is also an ADR-001 parity break. |
| `a: 0\|1\|…\|1999` | `RangeError: Maximum call stack size exceeded`; n=1000 is fine, n=2000 dies. Kills all six tools, `canon` and `summary` included, so confinement is not the mitigation. `trust.budget.depth` does not bound it. |
| a `.json` include | `TypeError` at `dist/val/MapVal.js:403`, reached while rendering the error message. |

The eight in-process tests all call `handle()`/`callTool()` directly and
would each have thrown the same exceptions; no test spawns
`bin/aontu-mcp.js`, and `main()` carries a coverage-ignore marker while
`bin/` is excluded from the coverage script — so the ADR-002 floor is
satisfied over an entry point nothing executes.

Smaller, but worth fixing in the same pass: `protocolVersion` is
hard-coded to `2024-11-05` and echoed regardless of what the client
requests (SDK 1.30.0's latest is `2025-11-25`); every tool takes document
*text* rather than a path, so an agent must transmit 49 KB to receive a
45-byte slice — inverting the token argument that justifies `get` — with
no cache and no `file`/`uri` parameter; there is no write verb (`set`) and
no `subsume`; and no `mcpServers` configuration stanza appears anywhere
in the repository. `diff` is the one tool with no CLI equivalent, which
matters because the module claims every tool returns the contract the CLI
prints.

## 4. Cross-port verdict flips, in both directions

> **Correction (2026-08-25).** All of the flips this section names
> are fixed, and a SIXTH was found afterwards by the automated review
> on PR #72: a quantifier applied to `\b` or `\B` — the same
> "nothing to repeat" disagreement as `^{1}`, which the first sweep
> covered for the two anchors only, on a comment asserting the word
> boundaries "quantify identically in both". Measured, they do not.
> The shared row that appeared to pin it tested a quantified
> BACKSPACE: one backslash in a source cell is the string escape,
> where a regex needs two, so the row passed while the real case
> diverged. Renamed, with the boundary rows it was standing in for
> added — and with the escaping trap written into the file's comment,
> because it will be walked into again.

The deployment the review implies — author with the TypeScript CLI,
enforce with the Go binary at a gateway — is unsafe today, and not only
in the direction the open issues describe.

**Go accepts what TypeScript refuses.** With schema `a: f(1)(2)` and data
`{}`: TypeScript `verdict: invalid` / `unknown_function` / exit 1; Go
`verdict: valid` / `findings: []` / exit 0. The same shape holds for
`path([1,2])` (#60) and for the path segment `-0` (#67) — and the sweep
that produced #67 was too narrow: `-00`, `- 0` and `-0.0` diverge
identically, so a guard written against the literal string `-0` misses
three spellings. Two further constructs flip on `re()` subset handling
and are tracked by no issue at all. **The flip fires from the data side
too** (`a: integer` against a data file containing `a: f(1)(2)`), so an
agent- or attacker-supplied document is a live vector, not just a
defective schema. Go is not blindly permissive — it keeps enforcing every
other constraint in the document — so the precise hole is that a path
constrained *only* by the mishandled construct goes unchecked.

**And TypeScript accepts what Go refuses**, which no issue records at
all. `a: string & re("^a{1001}$")` against 1,001 `a`s: TypeScript
`verdict: valid`, exit 0; Go `verdict: error`, exit 4, with
`findings: []`. The threshold is exactly RE2's 1000-repeat cap — n=1000
agrees, n=1001 diverges. **This is a normaliser gap, not a permanent
divergence**, and calling it one would reverse ADR-003: Aontu defines
the pattern language and rewrites a pattern before either host compiles
it, refusing only what cannot be rewritten. A repeat count RE2 will not
accept is exactly such a construct, and today neither `normaliseRe` nor
its portable-subset check mentions repeat counts — the refusal an agent
sees is RE2's own compile error surfacing through Go, which is the
failure mode ADR-003 exists to prevent. Both ports should refuse (or
bound) the range identically, and it earns real spec rows once they
agree.

Related, and confirmed against `vet` rather than only `why`: under an
`@"…"` include the Go port **names the wrong file** in a finding's site
while reporting the right row and column, so an agent applying a patch
from `sites[].file` + row + col edits an unrelated line of a different
file (#66). `progress.md:308` claims byte-identical reports and G7 phase
4 claims *"a site names its file in both"*; both need the carve-out.

None of this is recorded in `test/spec/divergent.tsv`. Its zero data
rows are correct and by design — the ledger is commentary only, because
a row there would be executed by both runners and could not pass in
both — but its entries cover one open divergence (#24, the lone
surrogates) and none of the verdict-flipping constructs above.

## 5. The repair loop has no third step

The diagnosis half is genuinely good, and better than most schema tools.
One `aontu vet` returns *every* violation — seven independent findings
across seven constraint kinds in one run, `truncated: false` — each with
`{code, class, severity, path, message, sites[{file,row,col,role,value}]}`,
sited on **both** documents with real line and column, data site first
because that is the one to edit. `expected` is the admissible set as an
algebra term (`"integer&min(1024)&max(65535)"` beside `"actual": 80`),
which is what an LLM needs to emit a correct replacement without
guessing. Exit codes are a real four-way verdict class. `aontu get $ -c`
answers *"what would have unified"* for a whole document in 300 bytes.

The repair half does not work.

- **`set` cannot narrow a pinned literal.** Running the loop the skill
  prescribes: schema `replicas: integer & above(0) & below(10)`, data
  `replicas: 42` → `vet` reports it correctly, `why` names the site, and
  `set '$.replicas=5'` answers `verdict: invalid`, `written: false`,
  exit 1. Because unification only narrows, **every `vet` failure of the
  commonest kind — the data pins the wrong value — is unrepairable by
  `set` by construction.** It succeeds only where the document left a
  hole (`replicas: number`).
- **The manual fallback corrupts files.** `Site` is a point with no
  extent (`ts/src/site.ts:12-14`), and the `canon` a contribution reports
  is not its source text: for `port: 0x1F`, `why` reports canon `"31"` at
  column 7, so a `(col, len(canon))` replacement writes `port: 5x1F`.
  This is not hypothetical — the LSP already ships the same arithmetic at
  `ts/src/lsp.ts:357`, where hovering `0x1F` highlights `0x` and hovering
  `1F` returns null.
- **`vet`'s `error` verdict carries no diagnostics at all**, in both
  ports: `findings: []`, empty stderr, exit 4, and the text renderer
  prints one line. The agent is told the schema is at fault and given
  nothing to act on — while `aontu <schema>` renders the fault in full,
  so the information exists and is dropped at the vet renderer boundary
  (`ts/src/vet.ts:359`, `:368`).
- **Data parse errors lose their location** in the machine-readable path
  (`row: -1, col: -1`) though the human renderer prints an exact caret.
- **Nothing has ever run the loop end to end.** There is no integration
  test that plays emit → vet → why → patch → re-vet; the spec suite pins
  each verb in isolation. Walking it by hand is what surfaced the
  `Site`-has-no-extent defect.
  *(Fixed 2026-08-25, item 7 of "Next" below: `cli-repair-loop` in
  `ts/test/cli.test.ts` and `go/cmd/aontu/repairloop_test.go` drive the
  whole loop through the command in both ports, asserting the exit code
  at every step — including the two arms that do not close, a pinned
  value that refuses the repair and a schema that does not stand up.)*

One CLI-wide hazard belongs here because of how it fails: **an
unrecognised verb is silently treated as a filename, last one wins**, so
`aontu vet2 schema.aon good.json` prints `good.json` and **exits 0**. In
a tool loop a typo produces a plausible success. `diff` is not a CLI verb
in either port and fails exactly this way. *(Fixed 2026-08-25 — see the
correction at the top of this section.)*

## 6. `*8080 | integer` is `number | integer`

The most consequential semantic finding, and the one that most directly
undermines *"type safety through unification"* for an agent.

A preferred scalar unifies as its base **kind**. So `port: *8080 |
integer` — the default idiom, written verbatim at
`docs/skill/examples.md:38` — accepts `3.5`, in both ports:

```
service: { name: string, port: *8080 | integer }   vs   {"port": 3.5}
→ verdict: valid   (TypeScript and Go, exit 0)
```

The mechanism is the spec's **family gate**, deliberately pinned by
`test/spec/pref.tsv` (`pref-family-gate-*`), so this is specified
behaviour and not a regression. But its consequence is that every key
written with the documented default idiom is silently widened from
`integer` to `number`, and the document that teaches the idiom is the
7 KB corpus an agent is meant to learn from. Whatever the resolution —
change the fold, or document the widening loudly and give the skill a
different idiom — the two cannot both stand as they are.

A neighbouring trap, confirmed: `[string]` is **positional** with an open
tail, so it admits `["core", 7]`. `[&: string]` is the working
list-of-`T` form, and the skill never shows `&:` on a list.

## 7. Teaching material: written, unshipped, partly wrong

`docs/skill/SKILL.md` is textbook Agent Skills format — valid
`name`/`description` frontmatter, a 293-character trigger description, a
158-word body, progressive disclosure into three siblings — and its first
substantive sentence pre-empts the single most damaging misconception:
*"Two documents do not override each other, they unify."* That is the
right thing in the right place.

It is also not installable anywhere. There is no `.claude/`, no plugin
manifest, and `docs/` cannot ship in the npm tarball. Its two outbound
links (`../../test/spec/errcodes.tsv`, `../../grammar/aontu.gbnf`) escape
its own directory, so both dangle the moment it is copied to a real skill
path. It never says how to obtain the binary.

The content has drifted from the engine in ways nothing tests:

- **`grammar-card.md` is untested by anything** (no test reads it, and it
  contains no fenced blocks to run) and is wrong or misleading on five
  rows: `must(cond, "why")` — the first argument is a constraint atom,
  not a condition, and there is no comparison operator, so
  `must($.a >= $.b, …)` is unspellable; `type(x)` — a bare identifier is a
  string, you need `$.Name`; a bare `a | b` cannot generate; `deprecate`
  surfaces only under `vet`/LSP; and arithmetic, where `+` is the only
  operator. It claims to be *"everything the language spells, on one
  page"* while omitting nine of `reference-language.md`'s thirty
  sections, the whole `pack`/`each` sublanguage included.
- **`docs/how-to.md` teaches that unification overrides.** Its "Reference
  and reshape" example is annotated `# copy base, override tier`, claims
  an output, does not parse as written, and — with the parse fixed — is a
  hard conflict. It contradicts the tutorial, the skill and the language.
- **`ts/test/skill.test.ts` cannot catch any of this.** It asserts only
  that examples `unify()` without error — never that they `generate()`,
  never what they produce — and skips two of the eight blocks, which are
  exactly the two that misbehave.
- **The arithmetic trap is whitespace-dependent**, which is worse than
  uniform: `a: 6/2` yields the string `"6/2"` with exit 0, while
  `a: 6 / 2` is a parse error; `a: -1` is fine, `a: 0-1` is a parse
  error. `vet` does catch `"6/2"` against `timeout: integer`, so the
  silent case is bare evaluation.
- **100 error codes are registered and roughly a quarter are explained
  nowhere.** The engine already holds per-code prose in `ts/src/hints.ts`
  and prints it on failure, but there is no way to ask for it — an
  `aontu explain <code>` verb would turn 100 opaque codes into 100
  self-documenting ones for near-zero cost.

`aontu agentsmd` is the strongest artifact in this area: byte-identical
across ports, idempotent, marker-spliced, preserving the surrounding
file, and carrying a canon-hash pin that `aontu hash` reproduces. Its
stanza, though, teaches no language, no `--format json` and no exit codes
— the three things a tool loop needs — and its `Shape` line is a depth-2
render that shows `top` for every leaf.

## 8. The grammar is a canon grammar, and the two files disagree

Both files load in real toolchains — `aontu.lark` under lark 1.3.1 with
Earley *and* LALR, `aontu.gbnf` under XGrammar 0.2.4 unmodified — which
most projects shipping a "published grammar" fail. All 28 builtins and
all 9 kind keywords are present in both, so the update discipline has
held. The canon corpus passes 715/715.

The caveats matter more than the register records:

- **The two files accept different languages.** `aontu.lark:99` is
  `%ignore /[ \t\n\r]+/`, which discards whitespace at every token
  boundary, while the `.gbnf` places `ws` explicitly and deliberately
  omits it at `func`'s paren and around a reference's dots. So `min (1)`
  and `$ . a . b` are accepted by the lark, rejected by the gbnf — **and
  accepted by the engine**, which makes the gbnf the wrong one, on the
  most natural whitespace habit a model has.
- **Over-approximation is dominated by two one-character bugs.** Of 1,200
  samples generated from the gbnf's own choice points and accepted by
  both toolchains, 150 fail to parse in the engine; 123 of those contain
  a bare `$`, because `ref ::= "$" ( "." segment )*` uses `*` where it
  needs `+`, and 16 more contain `-` inside a segment. Fixing those two
  characters drops the failure rate from 12.5 % to 0.7 %.
- **It is an emission grammar for canon, not for the authoring surface.**
  It accepts about 1 % of the suite's author-written sources and one of
  the seven Aontu documents in the shipped skill, because canon quotes
  every key and braces the root. The gbnf header does declare this — but
  `docs/skill/examples.md:12` tells the agent in prose that the excluded
  spelling *"also parses, so this is the same document"* one line after
  showing the only spelling the grammar allows.
- **It names a builtin the engine does not have**: `same`. The drift
  guard compares rule identifiers, not the contents of the `name` rule,
  so nothing can catch it. Go already exposes `BuiltinFuncNames()` for
  exactly this assertion.
- **The parity test is structurally blind to canon drift**, because its
  corpus is canon-mode rows only. Canon emits `$.q.$"SELF"` and
  `.$"KEY".x` — both verified fixed points — and both grammars reject
  them.
- **llguidance can load neither file** (the lark's entry rule must be
  `start`, not `root`; the gbnf converter rejects alternatives on
  continuation lines). Both are formatting-class issues, and a single
  smoke test would have caught them.
- It ships nowhere: not in the npm package, unmentioned in `README.md`,
  not served by the MCP server. It exists in git and at a raw URL.

Separately, and larger than the grammar finding that surfaced it:
**canon does not round-trip.** `a:min(true)` canonicalises to
`{"a":constraint()}`, and feeding that back answers
`[aontu/unknown_function]`. Canon is the basis of the hash, the diff, the
pins and the grammar corpus, so a non-reparseable fixed point is worth a
row of its own.

## 9. The register is accurate; its siblings are not

The register itself came out of this well — see
[§1](#1-what-has-landed-is-real). What has drifted is everything around
it, and one thing inside it.

**Inside it.** G7 phase 7 is marked LANDED, and its `--jsonl` session
mode does not exist in the Go port: `printf ':help\n' | aontu --jsonl`
answers `unknown option --jsonl` and exits 2, because `jsonl := false` at
`go/cmd/aontu/main.go:399` is never reassigned — the argument switch has
no case for it — while `helpText` at `:52` advertises the flag and
`repl.go` carries the full machinery behind it. The Go test passes
because it constructs `replState{JSONL: true}` directly, bypassing the
parser, so the suite is green over unreachable code. The phase's other
deliverables are fine: `:load`, `:keys`, `:get` and `:why` all answer
correctly in the Go REPL. By ADR-001 the honest status is PARTIAL, and it
is flipped below. In TypeScript the flag exists but is gated on
`process.stdin.isTTY`, so an agent piping commands gets them parsed as
Aontu source — the mode is reachable only through a pty, interleaved with
readline's escapes.

Four self-contradictions inside `progress.md`: a G5.5 note grading
PARTIAL a phase the table marks LANDED (and describing a *different*
phase's deliverables); a G4 note reading *"no G4 artifact beyond phases 0
and 1"* directly below six LANDED rows; protocol rule 5 and the
corrections section making mutually exclusive claims about the gap
documents; and — the one with the widest blast radius — **the G6 and G7
phase tables carry three-column headers over four-column rows**
(`progress.md:642`, `:748`), so every markdown renderer silently drops the
Pin column and a reader on GitHub sees the distribution layer and the
whole machine-access surface as twelve phases with no evidence at all.

**Around it**, in rough order of how much damage each does to an agent:

| document | what it says | what is true |
|---|---|---|
| `AGENTS.md` | *"`vet` is the one mode with a fifth column"*; documents 7 of 18 spec modes | six other modes are five-column. `CLAUDE.md` sends an agent here **first**, so this is the top-ranked doc defect: it will produce a wrong spec row. |
| `index.md:16` | *"Sixteen of forty-nine phases have moved"* | forty-nine have. `:319` adds *"Phases B and C are untouched"* when B and C are complete but for G5.6 — so the review's own entry document says the entire G3/G6/G7 surface does not exist. |
| `CHANGELOG.md` | newest entry is `re()` | zero mentions of the eleven verbs, the MCP server or SARIF. |
| `index.md:327,338` | *"now 17"* builtins; *"gained three modes"* | 28 builtins; fifteen new modes. A strikethrough correction reads as freshly checked, which makes a stale one worse than an obviously old number. |
| `docs/test-coverage.md:53,104` | 2,852 rows across 76 files | 3,054 across 86 — the exact duplication protocol rule 5 forbids. |
| `status-2026-08-17.md` | four "Next" items | all four are done; its disclaimer protects a top-down reader but not an agent landing mid-file. |

The structural fix for the whole class is worth more than the individual
edits: **a count that lives in two places will always rot**, so the
gap documents and `test-coverage.md` should link rule 5 rather than
restate it, and a `grep` for frozen row counts belongs in `make check`.
