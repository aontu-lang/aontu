# Status report — 2026-09-05

*A dated snapshot of one assessment, not a register.*
[`progress.md`](progress.md) remains **authoritative** for per-phase
status. This file records what an audit of the whole capability review
found on 2026-09-05 — every gap document, every register row, the
design notes that arrived outside the numbered plan, the three sibling
repositories, and the open-debt ledgers — and what it changed. Where
the two disagree, the register is right and this file is stale.

## Headline

**The numbered programme is done and released. The record has stopped
describing the programme.**

Sixty-seven register rows: fifty-one landed, four partial, eight not
started, four landed and then retired by an ADR. Every status word held
against the tree but one (G9 phase 4, regraded here). `aontu@0.57.0`
and `go/v0.1.15` were published this morning from the merge of #148,
the fourth release in eight days, and both test suites pass at that
head. Nothing in the eight gaps the survey opened is missing.

What the register cannot see is where the work went. Since the last
report on 2026-08-28 the tree gained twelve ADRs, two new verbs
(`view`, `fmt`), the language's first aliases, recursion, graph atoms,
first-class paths, a declared signature registry, text includes, four
string builtins and `emit` — about a thousand shared rows, of which
some seven hundred are pinned by no register row, because the
register's own scoping rule admits only "a numbered phase of a gap
document's implementation plan". Twelve design notes now carry phase
tables of their own; six of them the register never mentions; two of
them open with *"Status: PROPOSAL (nothing here is built)"* above
tables that say LANDED.

And the tree has moved under the record in the other direction too.
Eleven statements this audit found in the register describe engine
behaviour the engine no longer has, or never had: a "known limit" that
ADR-011 removed, a defect marked unfixed that resolves in both ports,
a Go graph bug closed by ADR-014 still marked NOT FIXED, three retired
artifacts still cited as pins, "an MCP tool in both ports" where Go
serves none. All are corrected in this commit. Below them sits a
shorter list the record does not mention at all: a same-value
disjunction that generates in TypeScript and refuses in Go, a
subsumption verb that grades an invalid document *undecided*, module
verbs that run outside the trust contract, and a use-case corpus that
CI has only ever run under one of the two ports — under the other, six
of sixteen cases fail.

## Method, and its confidence

Eighteen auditing agents worked the tree in parallel — one per gap
document, three over the design notes, and five sweeps (the register's
internal consistency, the open-debt ledgers, the three sibling
repositories, the release state, and the plan's completeness as a
description of the programme). Each was held to the register's own
evidence rule: a path, a symbol, a measured row count, a command with
its output, or a commit. Every claim of behaviour was probed through
**both** CLIs. They returned 265 findings.

Every high- and medium-severity finding then went to a second,
independent agent whose brief was to **refute** it — re-open the file,
re-run the command, re-count the rows, re-probe both ports, and search
the record for the omission the finding alleged. Of the findings so
judged, all but two survived (the two: a commit hash that "did not
exist" in a shallow clone but exists upstream, and a register omission
the register does not in fact make). The verification section at the
end carries the counts.

Two process facts belong in the record. The first run of the audit was
discarded whole: a harness fault rejected every tool call the nineteen
agents made, so each returned a report saying it had read nothing, and
the orchestration layer rejected even those. The second run went
through a different agent path. A session rate limit then killed
fifteen of the seventeen skeptics mid-run; they were re-run after it
reset. Neither fault touched the tree; both are why this report took a
day.

The tree the auditors read was `main` at `037ed6a`. While they read
it, #148 merged as `05a8760` and released 0.57.0. Every count in this
report and every correction in this commit was re-derived at
`05a8760`; where a finding was made against the earlier tree and the
merge changed the fact, the text says so.

As before: **this is written by the agent that did the work.** This
time the checks were re-derived by independent agents, which the
earlier reports did not have. It still has no human verifier.

## 4. What the tree does that the record does not say

These are behaviours, not bookkeeping. Each was reproduced through
both CLIs by an auditor and again by a skeptic, or by the author of
this report directly. None is in `test/spec/divergent.tsv`, BUGS.md or
the register unless the entry says so.

1. **`x: 1 | 1.0` generates `1` in TypeScript and refuses
   `disjunct_no_gen` in Go.** The same-value fold compares generated
   JSON text on one side and `reflect.DeepEqual` over an `int64` and a
   `float64` on the other. The number model says the two alternatives
   are kept (R3), so Go follows the record. An ADR-001 divergence on
   the canonical port's side, pinned by no row and absent from the
   ledger.
2. **`subsume` and `breaking` grade an invalid document
   `undecided`.** For `a: must("0 < $")` — a `func_arity` refusal —
   `vet` says invalid and exit 1; `subsume` says `sub_unresolved`,
   exit 3, in both ports; `breaking --allow-undecided` then passes it.
   The language reference says a source that does not stand alone
   answers `error` before the walk, and the code comment calls the
   fold that produced this unreachable. The evolution gate lets an
   unusable schema through as a maybe.
3. **The `mod` verbs run outside the trust contract.** `mod tidy` and
   `mod verify` evaluate vendored modules with no capability and refuse
   `--trust` and `--include-root` as unknown options, in both ports —
   while `docs/trust.md`, `--help` and the API reference say every verb
   takes them. A vendored module whose include escapes the project is
   evaluated silently by `verify` and denied by the bare command under
   `--trust root:.`. (`fmt` refuses the flags too, and resolves no
   include, so it is a wording fix; `mod` is not.)
4. **The G5.6 warning window covers the bare command and stdin
   only.** The row and trust.md clause 4 say every escaping resolution
   under the default warns; `vet`, `get`, `why`, `hash` and the REPL's
   `:load` resolve the escape silently in both ports. The narrowing is
   stated in a code comment ("stays a bare-command nicety") and
   nowhere else.
5. **`relation_cycle`'s path differs between the ports when the atom
   arrives through a reference.** `S: {dependsOn?: rel() & acyclic()}`
   applied as `$.S & {...}` reports `$.S.dependsOn` in TypeScript and
   `$.services.a.dependsOn` in Go; through `type()` the two swap
   sides. The shared rows for the code are `errc`, which cannot see a
   path.
6. **Two-site error frames order their operands differently.** For
   `l: [&: integer, 10, 20, "bad"]` and its map and filter cousins the
   code, path and both sites agree, but TypeScript shows the
   later-in-source frame first and Go the earlier, and the "Cannot
   unify value: X with value: Y" line reverses. `err` rows match a
   substring, so the suite cannot see it either.
7. **A refused `re` pattern is not refused until it meets a peer.**
   `a: re("(a+)+$")` alone canons as `{"a":constraint()}` — which does
   not reparse — and `aontu hash` pins it, in both ports. The gap
   document promised a located refusal at construction.
8. **`mod manifest --against` passes `port: 8080` → `port: integer`.**
   ADR-022 names this hole (determination); the landed gate is G3's
   backward check, which already refuses a changed default, so the
   ADR's own example overstates the gap while the hole it names is
   real.
9. **The use-case corpus has only ever run under TypeScript.**
   `run-all.sh` and the CI job drive the TypeScript CLI; every check
   honours an `AONTU` override. Under a Go build of the same commit,
   six of sixteen cases fail — 02, 03, 05, 07, 09 and 15 — including a
   silent value difference (`logLevel` "warn" against an expected
   "info"), a different error class, and in 15 a `view doc --out
   --check` that exits 1 from Go over a figure byte-identical to
   TypeScript's. The ledger and BUGS.md §42
   both name this blind spot as the reason a Go-only defect once hid;
   it is still open, and the six divergences are recorded nowhere.
10. **Four GitHub issues still reproduce; three are stale.** #61 (Go
    prints `null` and exits 0 where TypeScript refuses `no_gen`), #62
    (a dot chain in an implicit list resolves differently), #63 (frame
    order, item 6 above) and #67 (`$.a.-0` generates in Go, refuses in
    TypeScript) reproduce on `main`. #128 (should the CLI grow `fmt`),
    #59 and #60 are fixed and pinned.
11. **BUGS.md §27 is now a divergence recorded nowhere** — TypeScript
    still names the phantom `$.mod.spec.port`, Go answers the expected
    path — and the ledger's OPEN entry for #76 no longer diverges on
    its own recorded input.
12. Smaller, all confirmed: a keyed include directive is sited at
    column 4 in TypeScript and column 1 in Go; a hyphenated key inside
    `path()` is refused at parse in Go and at arity in TypeScript; the
    `rel_address` message names its two operands in opposite orders;
    `subsume` and `breaking` print `verdict: error` with no diagnostic
    where `trim --check` carries an `errors` array.

## 5. The plan no longer describes the programme

The register's scoping rule — an entry is "a numbered phase of a gap
document's implementation plan" — was right when every phase was one.
It now excludes most of what lands. Twelve of the twenty-one design
notes carry phase tables; the register mentions phases of six, all as
prose under G1 or G3; six it never names (ENV, FMT, INIT, ONTOLOGY,
VIEWS, VIEWS-ORDER). Two of the notes it does not name defer to it for
status. The result, measured: **706 of 4,324 shared rows — sixteen per
cent, at `037ed6a` — are pinned by no register row**, and roughly five
hundred of those are cited nowhere in the register at all. The
protocol says nothing in the register is machine-checked and the
same-commit rule is the whole mechanism; a rule that does not apply to
`fmt.tsv` cannot keep `fmt` current.

The same gap runs through the plan's own edges:

- The sequencing table's unnumbered Phase C items: **incremental LSP**
  is not built, is owned by no note or row, and both servers use full
  document sync, while the index says "Phases B and C have since
  landed"; **JSON Schema interop** is export only, and no plan item
  anywhere names import, which SUPPORT.md calls "the migration path";
  **views** shipped with 227 rows and no row.
- G9's third amendment names the template surface as "a new phase";
  the design's table carries it as "new, after 6", unnumbered, and the
  register has no row. Phase 6's manifest, coverage report and
  provenance trace are specified only in the gap document the row
  tells the reader not to read for them. MODELS.0.md's M0, which gates
  phase 1, is tracked nowhere.
- G6 and G10 against the September ADRs: ADR-022 is cited by no
  document in the review. The G10 paragraph still says the naming rule
  "needs no code" and no spec row, which parts 1 and 4 of ADR-022
  contradict (the major leaves `MODULE_RE`; `./` becomes mandatory);
  the G6.4 row keeps the OCI artifact, the `@1` major and the
  subsumption-only gate; rows 4 and 6 still plan OIDC binding,
  cosignatures and a cosignable checkpoint for a log the project will
  not run; ADR-021's private tier has a phase in neither repository;

- G5.6's prerequisite: REVIEW.md and SUPPORT.md both say the
